# ADR-033 — لینک امضاشده عکس هر run برای n8n و حذف metadata

تاریخ: ۳۱ اکتبر ۲۰۲۶. وضعیت: تصمیم فنی برش دوم گام ۴ [DEVELOPMENT_PLAN](../DEVELOPMENT_PLAN.md)، ادامه [ADR-032](ADR-032-n8n-extraction-run-contract.md) و [ADR-022](ADR-022-private-encrypted-asset-storage.md). PRD §۸ (n8n فقط از API داخلی scoped با TTL کوتاه داده ضروری می‌گیرد؛ fetch از URL نامطمئن ممنوع). **مجوز انتخاب provider AI، روشن‌کردن استخراج در production یا پایان گام ۲ نیست.**

## زمینه

ADR-032 فقط شناسه عمومی و metadata عکس را به n8n می‌داد. workflow بدون بایت عکس کار نمی‌کند. ADR-022 می‌گوید فایل اصلی با EXIF و GPS کامل ذخیره می‌شود و هر نسخه‌ای که به n8n می‌رود باید metadata نداشته باشد. PRD می‌خواهد دسترسی n8n «scope-bound» و کوتاه‌مدت باشد و n8n فایل را از URL نامطمئن (مثلاً لینک تلگرام) نگیرد.

## تصمیم

۱. **یک لینک برای هر عکس هر run:** envelope ورودی برای هر عکس `download_url` دارد:
   - مسیر: `GET /api/webhooks/internal/n8n/runs/{run}/assets/{asset}?expires=…&signature=…`.
   - `expires` دقیقاً مهلت run است. لینک با مهلت دیگر پذیرفته نمی‌شود، پس تمدید نمی‌شود.
   - `signature` یک MAC با کلید Workspace روی `run|asset|expires` است (`RunAssetUrlSigner`). نابودی کلید در حذف حساب همه لینک‌های آن حساب را بی‌اثر می‌کند. signed route خود Laravel از `APP_KEY` استفاده می‌کند که هیچ حذفی نابودش نمی‌کند، پس استفاده نشد.
   - تنها credential همین لینک است. کاربر یا Policy در این مسیر نیست. لینک فقط یک عکس از یک run را باز می‌کند.

۲. **شرط‌های سرو:** run وجود دارد، run هنوز باز است (`queued` یا `dispatched`)، Workspace فعال است، عکس جزو ورودی همان run و همان پروژه است، و امضا و مهلت درست است. امضا آخر بررسی می‌شود، پس برای run بسته یا حساب در حال حذف هیچ درخواستی به سرویس کلید نمی‌رسد. پارامتر آرایه‌ای یا تکراری هم همان ۴۰۳ است. هر شکست همان پاسخ `403 RUN_ASSET_FORBIDDEN` را می‌گیرد تا معلوم نشود کدام شرط رد شده است. پس از ثبت نتیجه، لغو، timeout یا درخواست حذف، لینک کار نمی‌کند.

۳. **حذف metadata** (`ImageMetadataStripper`) روی ساختار فایل، بدون decode پیکسل (dev image افزونه GD ندارد). هر سه قالب فقط allowlist ساختارهای تصویر را نگه می‌دارند:
   - JPEG: فقط segmentهای frame و جدول (SOFn، DHT، DAC، DQT، DNL، DRI) و داده scan می‌مانند. JFIF فقط با header ثابت و thumbnail صفر، Adobe فقط با header ثابت ۱۲ بایتی، و پروفایل رنگ ICC. بقیه APPn، COM، JPGn و marker ناشناخته حذف می‌شوند. داده پس از EOI حذف می‌شود.
   - PNG: فقط `IHDR`، `PLTE`، `IDAT`، `IEND`، `tRNS`، `gAMA`، `cHRM`، `sRGB`، `iCCP`، `sBIT`، `bKGD`، `pHYs`، `cICP` و chunkهای انیمیشن. پس `eXIf`، `exIf`، `zxIf`، `caBX` (C2PA)، `prVW`، متن، زمان و chunk خصوصی حذف می‌شوند. داده پس از `IEND` هم.
   - WebP: فقط `VP8 `، `VP8L`، `VP8X`، `ALPH`، `ICCP`، `ANIM` و `ANMF`. پرچم‌های EXIF و XMP در `VP8X` پاک و اندازه RIFF دوباره حساب می‌شود. داده پس از RIFF حذف می‌شود.
   - هر ساختاری که parse نشود رد می‌شود (`422 ASSET_METADATA_UNPARSEABLE`) و فایل همان‌طور فرستاده نمی‌شود. JPEG ناقص بدون EOI هم رد می‌شود.
   - فایل ذخیره‌شده تغییر نمی‌کند؛ فقط نسخه پاسخ پاک می‌شود.

۴. **پاسخ:** `Content-Disposition: attachment`، `Cache-Control: private, no-store` و `nosniff`، مانند دانلود کاربر (ADR-022). شکست یکپارچگی object همان `500 ASSET_INTEGRITY_FAILED` و لاگ critical فقط با شناسه است.

۵. **نشانی:** `N8N_APP_URL` نشانی‌ای است که n8n با آن به برنامه می‌رسد (ترجیحاً شبکه داخلی). لینک عکس و callback هر دو روی آن ساخته می‌شوند. خالی یعنی `APP_URL`. `N8N_CALLBACK_URL` هنوز می‌تواند callback را جدا تعیین کند.

۶. **سقف:** throttle ‏۶۰ درخواست در دقیقه برای هر run (کلید با حروف کوچک، پس حالت‌های مختلف یک شناسه یک سهمیه‌اند) و ۶۰۰ در دقیقه برای هر IP تا حدس شناسه ناشناس هم محدود باشد. یک run حداکثر ۲۰ عکس دارد.

۷. **schema:** `product-extraction.input.v1` فیلد اجباری `download_url` گرفت. نسخه v1 هنوز هیچ workflowی نداشت و پیش از اولین استفاده اصلاح شد. پس از اولین workflow، هر تغییر ناسازگار نسخه تازه می‌خواهد.

## بازبینی مستقل پیش از commit

بازبین جعل امضا یا استفاده دوباره لینک نیافت. دو P2 و سه P3 یافت؛ همه با آزمون اصلاح شدند:
- **(P2)** امضا پیش از وضعیت run بررسی می‌شد. در بازه حذف حساب، هر درخواست به OpenBao می‌رفت و ۵۰۰ می‌گرفت. ترتیب برعکس شد؛ آزمون روی ترتیب قبلی ۵۰۰ می‌گیرد.
- **(P2/P3)** PNG و WebP با denylist پاک می‌شدند و `exIf`، `zxIf`، `caBX`، `prVW`، `C2PA` و `exif` عبور می‌کردند. حالا allowlist است.
- **(P3)** پارامتر آرایه‌ای ۵۰۰ می‌داد. حالا ۴۰۳.
- **(P3)** JPEG باقی‌مانده APP0 پس از header و markerهای ناشناخته را نگه می‌داشت. حالا header ثابت و allowlist.
- **(P3)** کلید throttle به حروف حساس بود و سقف کلی ناشناس نداشت. هر دو اصلاح شد.


- **حذف metadata فقط در سطح ساختار است.** پیکسل‌ها دوباره ساخته نمی‌شوند. داده پنهان در خود تصویر (steganography) یا داخل frameهای انیمیشن می‌ماند.
- **پروفایل ICC کامل می‌ماند.** ICC ممکن است نام دستگاه یا نرم‌افزار را داشته باشد.
- **decode خروجی روی فایل واقعی آزموده نشده است.** dev image نه GD دارد نه Imagick. ساختار با `getimagesizefromstring` و fixtureها بررسی شد، نه با decoder کامل روی JPEG progressive یا فایل دارای ICC واقعی.
- **لینک تا پایان run قابل تکرار است.** هر کس لینک را داشته باشد تا بسته‌شدن run می‌تواند عکس را بگیرد. پس لینک نباید در لاگ یا execution history n8n نگه داشته شود (Runbook: pruning تاریخچه اجرای n8n).
- **مسیر از اینترنت عمومی بسته نیست.** محدودکردن `/api/webhooks/internal/` به شبکه داخلی در Caddy تصمیم عملیات است (ADR-032).
- **بررسی وضعیت بدون قفل است.** خواندن عکس در لحظه شروع حذف حساب ممکن است یک بار دیگر انجام شود. پس از نابودی کلید، رمزگشایی شکست می‌خورد.
- workflow واقعی n8n، provider و ربات زنده هنوز آزموده نشده‌اند.
