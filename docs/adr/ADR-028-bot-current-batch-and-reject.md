# ADR-028 — پروژه جاری ربات و دکمه رد محصول

تاریخ: ۲۹ اکتبر ۲۰۲۶. وضعیت: تصمیم فنی برش سیزدهم گام ۳، ادامه [ADR-027](ADR-027-bot-batch-finish-and-approval.md)، [ADR-026](ADR-026-bot-product-approval.md) و [ADR-024](ADR-024-telegram-photo-intake.md) (PRD §۶، FR-041). **مجوز intake واقعی در production، انتشار یا پایان گام ۲ نیست.**

## زمینه

تا ADR-027 ربات پروژه را ضمنی انتخاب می‌کرد: عکس و `/product` جدیدترین پروژه در حال ورودی را می‌گرفتند و `/done` قاعده دیگری داشت. فروشنده با چند پروژه باز نمی‌توانست پروژه را انتخاب کند. رد محصول هم فقط با API بود.

## تصمیم

۱. **پروژه جاری:** ستون `projects.bot_selected_at` (دقت میکروثانیه). هر پروژه تازه، چه با `/new` و چه با API، داخل تراکنش `CreateProjectAction` جاری می‌شود. `/projects` کنار هر پروژه باز (`collecting_input` یا `review_required`) غیر از پروژه جاری دکمه «انتخاب» دارد (`project:select:{id}`).
   - پروژه جاری: پروژه‌ای که آخرین بار انتخاب یا ساخته شده است، **در هر وضعیتی**. فقط اگر هیچ پروژه‌ای هرگز انتخاب نشده باشد (داده پیش از این migration)، جدیدترین پروژه باز جاری است.
   - عکس، `/product` و `/done` همه همین پروژه را می‌گیرند. اگر پروژه جاری دیگر در حال ورودی نباشد (بسته، تأییدشده یا لغوشده)، عکس و `/product` رد می‌شوند، و `/done` برای پروژه بسته پیام می‌دهد. ربات `/projects` یا `/new` را پیشنهاد می‌کند. پس ورودی هرگز بی‌صدا به پروژه قدیمی‌تری نمی‌رود.
   - دکمه‌های انتخاب `/projects` همه پروژه‌های باز (حداکثر ۱۰ جدیدترین) را پوشش می‌دهند، نه فقط ۵ پروژه فهرست‌شده.
   - انتخاب یک نوشتن است: مانند همه mutationها زیر قفل ردیف Workspace اجرا می‌شود و پس از درخواست حذف رد می‌شود (FR-086).
   - انتخاب فقط Policy `view` می‌خواهد و داده محصولی را تغییر نمی‌دهد، پس `version` پروژه بالا نمی‌رود. پروژه بسته، پروژه Workspace دیگر و پروژه ناموجود انتخاب نمی‌شوند. دو مورد آخر یک پاسخ دارند.

۲. **دکمه رد:** کارت محصول (`TelegramProductCard`) کنار «تأیید» دکمه «رد» با `product:reject:{id}:{rev}` دارد. همان `ArchiveProductAction` اجرا می‌شود، با نسخه مورد انتظار:
   - اگر محصول پس از کارت تغییر کرده باشد، حتی اگر از قبل رد شده باشد، `PRODUCT_REVISION_CONFLICT` و پیام «تغییر کرده است».
   - رد با نسخه مشخص فقط وقتی پروژه محصول هنوز در ورودی یا بررسی است (`collecting_input`، `needs_clarification`، `review_required`). کارت قدیمی هرگز محصول یک Batch تأییدشده را رد نمی‌کند (`PROJECT_STATE_CONFLICT`).
   - اثرانگشت idempotency درخواست API بدون نسخه مانند پیش از این تغییر است، پس replay درخواست‌های قبلی کار می‌کند. کلید idempotency از callback id است. هر رد پاسخ دارد. رد، عکس‌های واگذارشده ربات را آزاد می‌کند (ADR-026). API رد بدون نسخه مورد انتظار مانند قبل کار می‌کند.

## محدودیت‌ها و کار باز

- زمان انتخاب از ساعت سرور برنامه است. با چند سرور و اختلاف ساعت، ترتیب انتخاب‌های نزدیک ممکن است جابه‌جا شود. پایلوت یک سرور دارد.
- رد با API همچنان در هر وضعیت پروژه مجاز است (رفتار ADR-017/019).
- اصلاح محصول از ربات ساخته نشده است. رد و ارسال دوباره راه اصلاح است.
- reopen و لغو پروژه از ربات ساخته نشده‌اند.
