# ADR-047 — ویس در همان run استخراج و لینک امضاشده ویس

تاریخ: ۳ نوامبر ۲۰۲۶. وضعیت: تصمیم مالک درباره جریان ویس و نرخ آن، و برش اول اجرای آن. ادامه [ADR-045](ADR-045-openai-voice-and-text-processing.md) بند ۳ و ۴. قواعد run همان [ADR-032](ADR-032-n8n-extraction-run-contract.md)، [ADR-033](ADR-033-n8n-run-photo-links.md)، [ADR-038](ADR-038-n8n-run-claim.md)، [ADR-039](ADR-039-extraction-quote-and-credit-hold.md) و [ADR-042](ADR-042-usage-based-output-charge.md) است. **هیچ ویسی با این برش به n8n یا OpenAI نمی‌رود، هیچ نرخی تعیین نمی‌شود و استخراج همچنان خاموش است.**

## زمینه

ADR-045 دریافت امن ویس را ساخت و گفت متن ویس پیش از ورود به محصول باید برای اصلاح فروشنده نمایش داده شود (QA-04، FR-030). دو راه بود: یک run مشترک برای عکس و ویس، یا run جدای تبدیل گفتار به متن با تأیید متن و سپس run استخراج. نرخ ویس نیز باز بود و ADR-045 نرخ ساختگی را منع کرده بود.

## تصمیم مالک (۳ نوامبر ۲۰۲۶)

۱. **یک run برای عکس و ویس.** `/done` (و `finish-input` در API) ویس‌ها و عکس‌های تازه Batch را با یک پیش‌فاکتور و یک run می‌فرستد. n8n پس از claim هر ویس را با OpenAI به متن تبدیل می‌کند و سپس یک درخواست مدل با عکس‌ها و متن‌ها محصولات را استخراج می‌کند. متن هر ویس کنار کارت محصول «پیشنهادی» و به نقل از فروشنده نمایش داده می‌شود و پیش از Gate A قابل اصلاح است. هیچ مقدار ناشی از ویس بدون تأیید انسان نهایی نمی‌شود. زنجیره فعلی quote، hold، claim، لینک امضاشده و callback بازاستفاده می‌شود.

۲. **نرخ ویس پیش‌فرض ندارد.** تخمین پیش‌فاکتور برای ویس از یک متغیر محیطی اجباری بدون مقدار پیش‌فرض می‌آید. تا مالک عدد را ندهد، هیچ ویسی وارد run پولی نمی‌شود. Batch عکس‌دار همچنان استخراج می‌شود و به فروشنده گفته می‌شود ویس‌ها ذخیره‌اند ولی پردازش نمی‌شوند. کسر واقعی همان فرمول مصرفی ADR-042 است (token و درخواست مدل، حداقل کلاس، حداکثر سقف پیش‌فاکتور).

## قرارداد برنامه‌ریزی‌شده

- `product-extraction.input.v2`: مثل v1 به‌علاوه `voices` (شناسه، `mime`، `size_bytes`، `duration_ms`، `download_url`). فهرست خالی مجاز است.
- `product-extraction.output.v2`: مثل v1 به‌علاوه `transcripts` (شناسه ویس و متن) و `source_voice_ids` در هر کاندید. هر کاندید دست‌کم یک منبع عکس یا ویس از همان run دارد. usage مصرف تبدیل گفتار و مدل متن را با هم و بدون دوبار شمردن retry گزارش می‌کند.
- workflow تازه `product-extraction.openai.v2` با webhook جدا. `claim.v1` تغییر نمی‌کند. export `openai.v1` (ADR-046) با جایگزینی آن بازنشسته می‌شود؛ هیچ‌جا منتشر نشده است.

## برش اول (این تغییر)

- ستون `ai_workflow_runs.input_voice_ids`: شناسه عمومی ویس‌هایی که run اجازه خواندن دارد، به ترتیب. برای runهای قبلی null است. در این برش هیچ کدی آن را پر نمی‌کند.
- لینک امضاشده ویس `GET /api/webhooks/internal/n8n/runs/{run}/voices/{voice}`: MAC با کلید Workspace در context جدا از عکس (`ai_workflow_runs.voice_url`)، پس امضای لینک عکس برای ویس کار نمی‌کند و برعکس. انقضا همان مهلت run است. سهمیه درخواست همان سهمیه لینک عکس هر run است.
- `ReadRunVoiceAction` همان بررسی‌های لینک عکس را دارد: run باز و claimشده، Workspace فعال، provider و نسخه مجاز، ویس جزو ورودی همان run و همان پروژه. علاوه بر آن دریافت ویس باید همین حالا مجاز باشد: flag محیط، نبودن در production، بسته مصوبی که ویس را اعلام می‌کند و رضایت همان نسخه. همه ردها یک پاسخ ۴۰۳ دارند. حذف حساب، پایان run و گذشت مهلت لینک را می‌بندند.
- `OggOpusTagStripper` پیش از خروج، comment header (OpusTags) را با header خالی جایگزین می‌کند: نام برنامه ضبط، عنوان، تاریخ یا تصویر جلد نمی‌رود. صفحه شناسایی و همه صفحه‌های صوت بایت‌به‌بایت می‌مانند؛ فقط شماره صفحه و CRC دوباره ساخته می‌شوند. چیدمان ناشناخته رد می‌شود (`VOICE_DAMAGED`، ۴۲۲)، نه این‌که همان‌طور فرستاده شود. CRC صفحه Ogg در helper خالص `App\Helpers\OggCrc` است و inspector هم از آن استفاده می‌کند.

## شواهد

- `OggOpusTagStripperTest`: سه fixture، از جمله comment header دو صفحه‌ای با عنوان و نام برنامه. خروجی دوباره از inspector با همان مدت می‌گذرد و هیچ تگی ندارد. ورودی بدون صفحه صوت، بریده یا غیر Ogg رد می‌شود.
- `RunVoiceLinkTest`: لینک پیش از claim ۴۰۳ است و پس از claim ویس بدون تگ را با `audio/ogg`، `no-store` و `nosniff` می‌دهد. امضای صفر، انقضای دیرتر، بدون امضا، پارامتر آرایه‌ای، ویس دیگر همان Batch که به run داده نشده، امضای لینک عکس روی مسیر ویس و برعکس، خاموش‌شدن دریافت ویس، حذف حساب، مهلت run و run تمام‌شده همه ۴۰۳ هستند.
- بررسی با decoder واقعی: فایل Opus سه‌ثانیه‌ای ffmpeg با `title`، `artist` و `encoder`. پس از پاک‌سازی، ffprobe هیچ تگی نشان نداد، مدت ۳٫۰۰۶۵ ثانیه ماند و ffmpeg آن را بدون خطا decode کرد.

## گیت‌های باز و برش‌های بعدی

۱. انتخاب ویس‌های تازه Batch، سطر ویس در پیش‌فاکتور با نرخ اجباری بدون پیش‌فرض، envelope `input.v2` و export `openai.v2` با گره تبدیل گفتار به متن OpenAI. مدل تبدیل گفتار، سقف مدت هر run و سیاست retry پس از آزمون API واقعی تعیین می‌شوند.
۲. callback `output.v2`: ذخیره رمز‌شده متن ویس زیر کلید Workspace، منشأ ویس در هر مقدار پیشنهادی، نمایش متن کنار کارت ربات و اصلاح آن پیش از Gate A، و حذف آن با حذف حساب.
۳. بسته سیاست مصوب نام‌برنده OpenAI برای عکس و ویس، رضایت تازه فروشنده، عدد نرخ ویس از مالک، و آزمون API واقعی و staging. تا آن زمان این مسیر در هر محیطی بسته است.
