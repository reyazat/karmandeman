# ADR-031 — لغو پروژه از ربات

تاریخ: ۲۹ اکتبر ۲۰۲۶. وضعیت: تصمیم فنی برش شانزدهم گام ۳. ادامه [ADR-019](ADR-019-reopen-cancel-and-approval-integrity.md) و [ADR-028](ADR-028-bot-current-batch-and-reject.md) (PRD §۶، FR-063). **این ADR مجوز intake واقعی در production، انتشار یا پایان گام ۲ نیست.**

## زمینه

لغو پروژه (FR-063) فقط از API ممکن بود (`POST /projects/{id}/cancel`، ADR-019). فروشنده پایلوت با ربات کار می‌کند و پروژه اشتباه یا رهاشده را نمی‌توانست ببندد. پس پروژه در `/projects` باز و قابل انتخاب می‌ماند.

## تصمیم

۱. **`/cancel` فقط می‌پرسد:** `PrepareTelegramProjectCancellationAction` پروژه جاری ربات (ADR-028) را با Policy `update` می‌خواند. پیام نام پروژه و تعداد محصول فعال را نشان می‌دهد و می‌گوید لغو برگشت ندارد. دکمه «بله، پروژه لغو شود» داده `project:cancel:{id}:{version}` دارد. این مرحله چیزی نمی‌نویسد. لغو برگشت‌ناپذیر است، پس یک فشار تصادفی یا یک دستور به‌تنهایی پروژه را نمی‌بندد.
   - پروژه جاری بدون Policy یا پروژه جاری ناموجود: «پروژه جاری نداری».
   - پروژه جاری در وضعیت غیرقابل لغو (`isCancellable`، ADR-019): «قابل لغو نیست». در این حالت دکمه‌ای نمی‌آید.
   - برای `product_approved`، پیام هشدار می‌دهد که نسخه نهایی این پروژه دیگر خروجی معتبر نیست. snapshot پروژه لغوشده با `409 PROJECT_NOT_APPROVED` رد می‌شود (ADR-019).

۲. **دکمه تأیید:** `CancelTelegramProjectAction` همان `CancelProjectAction` API را اجرا می‌کند. یعنی idempotency، رضایت، قفل Workspace و Policy همان API است. کلید idempotency از callback id می‌آید.
   - اگر `version` پروژه پس از پیام تغییر کرده باشد (مثلاً محصول تازه یا تأیید)، پاسخ `PROJECT_VERSION_CONFLICT` است و لغو انجام نمی‌شود. ربات می‌گوید `/cancel` را دوباره بفرست. پس فروشنده همیشه همان چیزی را لغو می‌کند که دیده است.
   - پروژه Workspace دیگر و پروژه ناموجود یک پاسخ دارند: «پروژه یافت نشد».
   - درخواست حذف حساب پس از نمایش دکمه (رقابت با قفل Workspace): «حساب در حال حذف است»، نه «دوباره بزن».
   - هر رد پاسخ دارد و پرتاب نمی‌شود. انتخاب پروژه (ADR-028) هم پس از درخواست حذف همین پاسخ را می‌دهد و پرتاب نمی‌کند.

۳. **پس از لغو:** محصولات تغییر نمی‌کنند (ADR-019). پروژه لغوشده پروژه جاری می‌ماند (ADR-028). پس عکس و `/product` رد می‌شوند و ربات `/projects` یا `/new` را پیشنهاد می‌کند. ورودی بی‌صدا به پروژه دیگری نمی‌رود.

## محدودیت‌ها و کار باز

- لغو هیچ اعتباری آزاد نمی‌کند، چون تا گام ۵ رزروی وجود ندارد. وقتی Quote و رزرو ساخته شوند، `isCancellable` و آزادسازی FR-063 باید همراه هم بازبینی شوند.
- `/cancel` فقط پروژه جاری را لغو می‌کند. برای لغو پروژه دیگر، فروشنده اول آن را در `/projects` انتخاب می‌کند. `/projects` فقط پروژه‌های `collecting_input` و `review_required` را قابل انتخاب می‌کند. پس پروژه `product_approved` که دیگر جاری نیست فقط با API لغو می‌شود.
- دکمه رد کارت در پروژه لغوشده کار نمی‌کند (`PROJECT_STATE_CONFLICT`، ADR-028). رد برای آزادکردن SKU فقط با API است (ADR-019). محصولات ساخته‌شده با `/product` SKU ندارند، پس این محدودیت امروز SKU ربات را رزرو نگه نمی‌دارد.
- ربات زنده آزموده نشده است. آزمون‌ها Bot API را شبیه‌سازی می‌کنند.
