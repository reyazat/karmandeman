# ADR-027 — پایان ورودی و تأیید Batch از ربات (`/done`)

تاریخ: ۲۹ اکتبر ۲۰۲۶. وضعیت: تصمیم فنی برش دوازدهم گام ۳، ادامه [ADR-026](ADR-026-bot-product-approval.md) و [ADR-018](ADR-018-batch-finish-input-and-approved-snapshot.md) (PRD §۶، FR-041، FR-043). **مجوز intake واقعی در production، انتشار یا پایان گام ۲ نیست.**

## زمینه

پس از ADR-026 فروشنده در ربات محصول ثبت و تأیید می‌کرد، ولی «پایان ورودی» و تأیید Batch فقط با API بود. با این برش، کل برش عمودی گام ۳ (ورودی ← پیش‌نویس ← تأیید انسانی ← نسخه نهایی امضاشده) از ربات انجام می‌شود.

## تصمیم

۱. **`/done`:** همان پروژه‌ای که `/product` در آن می‌نویسد، یعنی جدیدترین پروژه `collecting_input`. اگر نباشد، پروژه‌ای در `review_required` که آخرین تغییر را داشته است (هر اصلاح یا تأیید محصول `updated_at` آن را جلو می‌برد).
   - اگر در `collecting_input` باشد، همان `FinishProjectInputAction` با نسخه جاری اجرا می‌شود (کلید idempotency از کلید پیام). پروژه بدون محصول بسته نمی‌شود و ربات می‌گوید اول `/product` بفرست.
   - سپس محصولاتی که هنوز Gate A ندارند فهرست می‌شوند. «تأییدشده» یعنی وضعیت `approved` و برابری نسخه تأییدشده با نسخه جاری، همان شرط تأیید Batch. هر کدام یک پیام جدا با نام، تعداد عکس، قیمت و واحد **نسخه جاری** و دکمه `product:approve:{id}:{rev}` همان نسخه (ADR-026) می‌گیرد، حداکثر ۱۰ پیام. پس دکمه هرگز بدون محتوایی که تأیید می‌کند نمی‌آید.
   - پروژه‌ای که همه محصولاتش رد شده‌اند دکمه تأیید نمی‌گیرد.
   - اگر همه تأیید شده‌اند، یک دکمه «تأیید پروژه» با `project:approve:{id}:{version}` نسخه‌ای که نشان داده شد می‌آید.
   - `/done` روی پروژه‌ای که در `review_required` است دوباره همین خلاصه و دکمه‌ها را با نسخه تازه می‌دهد.

۲. **دکمه تأیید پروژه:** همان مرزهای دکمه محصول (گفتگوی خصوصی، onboarding، الگوی سخت‌گیر). سپس همان `ApproveProjectProductsAction`: رضایت، قفل، Policy، وضعیت `review_required`، **برابری دقیق version**، تأیید همه محصولات، بررسی `approval_mac` هر نسخه و snapshot امضاشده.
   - هر تغییر محصول `version` پروژه را بالا می‌برد، پس دکمه‌ای که پس از تغییر زده شود رد می‌شود و کاربر `/done` را دوباره می‌فرستد.
   - کلید idempotency از callback id هر فشار است (ADR-026). پروژه Workspace دیگر و پروژه ناموجود یک پاسخ دارند. هر رد با پیام پاسخ داده می‌شود.
   - پاسخ موفق تعداد محصولات و شماره snapshot را می‌گوید. خروجی JSON همان `GET /projects/{id}/snapshot` است.

## محدودیت‌ها و کار باز

- **فایل JSON از ربات ارسال نمی‌شود.** ارسال فایل خصوصی از outbox نیاز به طراحی جدا دارد، چون payload صف با APP_KEY مشترک رمز می‌شود (ADR-013). این کار به خروجی‌های گام ۶ وابسته است.
- انتخاب پروژه ضمنی است. کاربری که چند پروژه باز دارد، ابتدا پروژه در حال ورودی و سپس آخرین پروژه تغییرکرده در بررسی را می‌بیند. پروژه دیگر در بررسی با تغییر یکی از محصولاتش جلو می‌آید. انتخاب صریح، reopen و لغو پروژه از ربات ساخته نشده‌اند.
- دکمه‌های محصول بیش از ۱۰ نشان داده نمی‌شوند. پس از تأیید آن‌ها، `/done` بعدی بقیه را می‌آورد.
