# ADR-045 — OpenAI در n8n برای پردازش متن و ویس

تاریخ: ۲ نوامبر ۲۰۲۶. وضعیت: تصمیم مالک درباره provider و مرز اجرا؛ **پیاده‌سازی چندرسانه‌ای و مجوز فعال‌سازی نیست**. جایگزین انتخاب Google در [ADR-037](ADR-037-gemini-extraction-provider.md) است، نه قرارداد امنیتی/مالی ADR-032…039.

## تصمیم

۱. **OpenAI تنها provider انتخاب‌شده برای پردازش AI محصول است.** متن آزاد محصول و ویس واقعی به Laravel می‌رسند، اما استخراج/تبدیل گفتار به متن و تحلیل متن فقط در n8n و با credential رمز‌شده OpenAI اجرا می‌شود. فرمان‌های ربات، نگاشت CSV و ثبت دستی `/product` پردازش AI نیستند و رفتار قطعی فعلی‌شان حفظ می‌شود. Laravel همچنان مالک هویت، Workspace، رضایت، فایل خصوصی، run، quote/hold، محصول و تأیید انسانی است؛ n8n به دیتابیس یا ledger دسترسی ندارد.

۲. **نسخه Gemini بازنشسته است، نه تبدیل‌شده:** export تاریخی `product-extraction.v1` هنوز Google را فراخوانی می‌کند و نباید برای هیچ run تازه‌ای dispatch یا claim شود. تا زمانی که export جدید OpenAI با نسخه و مسیر webhook متناظر ساخته، تست و انتخاب نشده است، شرط `extractionEnabled()` برای نسخه قدیمی false است. run قدیمی در صف بسته و hold آن آزاد می‌شود؛ لینک عکس run ناسازگار نیز داده نمی‌دهد. تغییر صرف نام provider در config مجوز فرستادن داده به workflow قبلی نیست.

۳. **قرارداد بعدی برای متن/ویس:** ورودی متن با شناسه پیام/پروژه، فقط پس از رضایت همان نسخه سیاست و quote پذیرفته‌شده، از outbox امضاشده به n8n برود. ویس با MIME واقعی، سقف حجم و مدت، dedupe و محل نگهداری رمز‌شده زیر کلید Workspace ثبت شود؛ n8n تنها پس از claim انحصاری Laravel، بایت را از لینک کوتاه‌مدت run-scoped و tenant-scoped بگیرد. transcript ابتدا برای اصلاح/تأیید فروشنده نمایش داده شود (QA-04/FR-030)؛ متن و transcript هر دو untrusted هستند، هیچ دستور داخل آن‌ها مجوز تغییر وضعیت یا ارسال به نشانی دیگر نیست. خروجی دارای evidence پیام/فایل، قیمت بدون واحد `null` و همه مقادیر `suggested` باشد و در Laravel دوباره validate شود.

۴. **هزینه و شکست:** قبل از هر تماس پولی، quote نسخه‌دار با سقف و tariff همان کلاس، رزرو اتمی و claim یک‌بار مصرف لازم است. usage واقعی OpenAI (هم STT و هم مدل متن، بدون دوبار شمردن retry) باید قابل تطبیق با صورت‌حساب provider و در حد سقف باشد؛ callback امضاشده، timeout و cancel همان قواعد release/capture فعلی را نگه می‌دارند. مدل‌های نهایی، قیمت STT و متن، محدودیت مدت و سیاست retry بعد از آزمون API واقعی و نمونه‌های با رضایت تعیین می‌شوند؛ برای آن‌ها نرخ ساختگی یا درخواست رایگان فرض نمی‌شود.

## گیت فعال‌سازی

- بسته سیاست مصوب تازه باید OpenAI را با `ai_processing.providers: ["openai"]` به‌عنوان پردازشگر متن، ویس و عکس نام ببرد؛ digest جدید و پذیرش تازه فروشنده لازم است. بسته فعلی مجوز آن نیست. سیاست ارسال داده، نگهداری OpenAI/n8n و حذف نسخه‌های پشتیبان باید با QA-19…21 و restore drill سازگار باشد.
- export و credentialهای OpenAI در n8n، اعتبارسنجی schema، تست امضای ورودی/claim/callback، آزمون tenant isolation و retry/هم‌زمانی روی PostgreSQL موقت، تست API واقعی با داده مجاز و تطبیق usage/هزینه پیش از روشن کردن flag لازم‌اند. هیچ درخواست واقعی، انتشار workflow، migration یا استقرار با این ADR انجام نمی‌شود.
- باز کردن extraction در production همچنان تصمیم و ADR انتشار جدا می‌خواهد. مسیر دستی تا آن زمان برقرار است.

## پیامد

کد فعلی فقط مرز provider را می‌بندد؛ هنوز دریافت ویس، قرارداد متن آزاد، workflow OpenAI، پیش‌نمایش transcript و quote این دو کلاس وجود ندارند. تست‌های قدیمی n8n درباره Gemini فقط سابقه workflow قدیمی‌اند، نه اثبات OpenAI.
