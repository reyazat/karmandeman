# ADR-032 — قرارداد اجرای استخراج محصول با n8n (برش اول گام ۴)

تاریخ: ۳۱ اکتبر ۲۰۲۶. وضعیت: تصمیم فنی برش اول گام ۴ [DEVELOPMENT_PLAN](../DEVELOPMENT_PLAN.md) («n8n با JSON Schema نسخه‌دار، signed callback، timeout/retry و cost cap»)، PRD E04، E07 (FR-060…064)، §۸ و ADR-001 در PRD. ادامه [ADR-022](ADR-022-private-encrypted-asset-storage.md)، [ADR-023](ADR-023-product-photos-from-batch-assets.md) و [ADR-027](ADR-027-bot-batch-finish-and-approval.md). **مجوز انتخاب provider AI، پردازش هزینه‌دار، intake واقعی در production یا پایان گام ۲ نیست.**

## زمینه

گام ۳ پایان یافت: ورودی دستی، Gate A، snapshot و JSON از ربات. گام ۴ استخراج چندرسانه‌ای با n8n است. شرط شروع آن «provider تأییدشده» است و provider هنوز انتخاب نشده است (PRD §۲۰). گام ۵ (Quote و رزرو اعتبار) هم پیش از هر پردازش هزینه‌دار لازم است و ساخته نشده است.

مرز اعتماد این گام مستقل از provider است: Laravel مالک وضعیت است و n8n adapter نامطمئن است. خروجی مدل حتی با امضای معتبر untrusted است (ADR-001). پس این برش فقط قرارداد اجرا را می‌سازد و استخراج را خاموش نگه می‌دارد.

## تصمیم

۱. **خاموش به‌طور پیش‌فرض:** `KM_AI_EXTRACTION_ENABLED` پیش‌فرض `false` است. در production همیشه خاموش است، حتی اگر روشن تنظیم شود (`AIWorkflowService::extractionEnabled`). روشن‌کردن در production ADR تازه می‌خواهد: provider تأییدشده، رزرو اعتبار گام ۵ پیش از run و تصویب سیاست.

۲. **شروع run:** `finish-input` (API و `/done` ربات، یک Action مشترک):
   - با استخراج روشن، فقط عکس‌های تازه Batch به یک run می‌روند: عکسی که محصول ربات claim کرده، نسخه جاری محصول API به آن ارجاع می‌دهد، یا ورودی run موفق قبلی بوده (حتی بی‌نتیجه)، دوباره فرستاده نمی‌شود. پروژه به `extracting` می‌رود و API ‏`202` برمی‌گرداند.
   - سقف عکس هر run: `KM_AI_MAX_ASSETS_PER_RUN` (پیش‌فرض ۲۰). بیشتر از آن `422 EXTRACTION_TOO_MANY_PHOTOS` است و run ساخته نمی‌شود (FR-023).
   - بدون عکس آزاد، یا با استخراج خاموش، مسیر دستی گام ۳ بدون تغییر اجرا می‌شود.
   - ردیف `ai_workflow_runs` و job شروع در یک تراکنش ثبت می‌شوند (صف database ‏`ai`، مانند outbox تلگرام در ADR-008). job فقط شناسه run را حمل می‌کند.
   - replay همان کلید idempotency همان پاسخ را می‌دهد و run دوم نمی‌سازد.

۳. **ورودی n8n** (`n8n/schemas/product-extraction.input.v1.json`):
   - `run_id`، شناسه عمومی پروژه، شماره تلاش، فهرست عکس‌ها با شناسه عمومی، نوع، حجم و ابعاد، سقف‌ها، مهلت و نشانی callback.
   - نام پروژه، Workspace، برند، شناسه تلگرام و بایت فایل در آن نیستند.
   - امضا: `X-KM-Timestamp` و `X-KM-Signature: v1=hex(HMAC-SHA256(secret, "{timestamp}.{body}"))` با `N8N_WORKFLOW_AUTH_TOKEN`.
   - فقط run در وضعیت `queued` شروع می‌شود. خطای شبکه یا HTTP غیر 2xx پرتاب می‌شود و job تا ۳ بار retry می‌شود (backoff ‏۱۰ و ۶۰ ثانیه). پس از آخرین شکست، run با `DISPATCH_FAILED` بسته می‌شود.

۴. **callback** (`POST /api/webhooks/internal/n8n/runs`، `n8n/schemas/product-extraction.output.v1.json`):
   - امضای همان قالب با secret جدا `N8N_CALLBACK_SECRET`. پس نشت یک جهت، جهت دیگر را جعل نمی‌کند. secret خالی همه را با `401` رد می‌کند. timestamp بیش از ۳۰۰ ثانیه دور `401` است. throttle ‏۱۲۰ در دقیقه.
   - بدنه با schema سخت بررسی می‌شود: کلید ناشناخته در هر سطح، نسخه دیگر schema، usage منفی یا غیرعدد صحیح JSON، قیمت بدون واحد، شیء قیمت خالی، مبلغ رشته‌ای یا boolean، عکس تکراری در یک کاندید و نامزد در پاسخ `failed` رد می‌شوند. هر کاندید سپس از همان قواعد فرم دستی می‌گذرد (`ProductDraftRules`). بدنه نامعتبر ‏`422 WORKFLOW_OUTPUT_INVALID` با مسیر فیلدها می‌گیرد و run با `OUTPUT_INVALID` شکست می‌خورد.
   - هر کاندید فقط به عکس‌های ورودی همان run ارجاع می‌دهد. عکس Batch یا Workspace دیگر رد می‌شود (FR-030).
   - **همه مقدارها `suggested` هستند.** مدل هرگز مقداری را تأیید نمی‌کند. پس هیچ محصول استخراج‌شده‌ای بدون تأیید انسان از Gate A نمی‌گذرد (PRD §11.1). قیمت فقط با واحد پذیرفته می‌شود و مانند فرم دستی به ریال تبدیل می‌شود. قیمت نامعلوم `null` است.
   - منشأ: `evidence` و `pricing.source` برابر `ai_extraction` است و هر evidence فهرست `source_asset_ids` دارد. این افزودنی به schema 1.0 رکورد محصول است؛ PRD §7.2 کلید مفرد `source_asset_id` را مثال می‌زند.
   - SKU پیشنهادی که در Workspace گرفته شده باشد کنار گذاشته می‌شود و محصول بدون SKU ساخته می‌شود.
   - هر عکس به اولین کاندیدی که به آن ارجاع داده claim می‌شود. عکسی که هیچ کاندیدی به آن ارجاع نداده آزاد می‌ماند.
   - پس از ثبت، پروژه به `review_required` می‌رود. بدون هیچ محصول فعال، به `collecting_input` برمی‌گردد. پیام ربات به درخواست‌کننده از outbox می‌رود.

۵. **حالت‌های پایان و مهار:**
   - n8n شکست گزارش کند، usage از سقف بگذرد (`USAGE_OVER_CAP`، لاگ critical)، درخواست‌کننده دیگر مجوز `update` نداشته باشد، یا رضایت سیاست نباشد: run شکست می‌خورد، هیچ محصولی ذخیره نمی‌شود و پروژه به `collecting_input` برمی‌گردد.
   - مهلت: `KM_AI_RUN_TIMEOUT_MINUTES` (پیش‌فرض ۱۵). `ai:expire-runs` هر دقیقه run گذشته از مهلت را `timed_out` می‌کند و Batch را باز می‌کند. run حساب در حال حذف انتخاب نمی‌شود و تا purge دست‌نخورده می‌ماند، پس صف انقضای دیگران را پر نمی‌کند.
   - اگر استخراج پس از بستن Batch خاموش شود، job شروع run را با `EXTRACTION_DISABLED` می‌بندد و Batch را همان لحظه باز می‌کند.
   - لغو: `extracting` قابل لغو شد، چون هنوز اعتباری رزرو نمی‌شود. لغو run باز را زیر همان قفل Workspace می‌بندد.
   - callback دیررس پس از لغو، timeout یا شکست: `200` با `discarded`. پس از درخواست حذف حساب هم `discarded` است و job شروع چیزی نمی‌فرستد (FR-086).
   - همان بدنه پس از ثبت موفق: `200 already_recorded`. بدنه متفاوت: `409 RUN_ALREADY_COMPLETED`. run ناشناخته: `404`.
   - قفل‌ها به ترتیب purge گرفته می‌شوند: اول ردیف Workspace، بعد ردیف run.

۶. **سقف هزینه** (PRD §11، FR-064): `KM_AI_MAX_MODEL_REQUESTS`، `KM_AI_MAX_INPUT_TOKENS`، `KM_AI_MAX_OUTPUT_TOKENS` و `KM_AI_MAX_CANDIDATES_PER_RUN` با هر run به n8n می‌روند و usage گزارش‌شده در callback دوباره با آن‌ها مقایسه می‌شود. usage (تعداد درخواست، token، provider و model) روی run ذخیره می‌شود.

۷. **حذف و نگهداری:** `ai_workflow_runs` در فهرست صریح purge است. ردیف run متن محصول ندارد: شناسه‌های عمومی عکس، وضعیت، کد خطا، MAC کلیددار بدنه پذیرفته‌شده و شمارش usage. تا حذف حساب می‌ماند.

۸. **استقرار:** سرویس `ai_worker` در `compose.prod.reference.yaml` صف `ai` را اجرا می‌کند و به شبکه‌های `app_db` و `workflow` وصل است. `N8N_CALLBACK_SECRET` اختیاری است و خالی‌بودن آن callback را می‌بندد.

## بازبینی مستقل پیش از commit

بازبین دور زدن امضا، replay مؤثر، نوشتن بین Workspaceها و گذر از Gate A نیافت. سه P2 و دو P3 یافت؛ همه جز یکی با آزمون اصلاح شدند:
- **(P2)** عکس‌های محصولات API و run بی‌نتیجه دوباره به مدل می‌رفتند و محصول تکراری و هزینه دوباره می‌ساختند. Batch دستی با عکس زیاد هم بسته نمی‌شد.
- **(P2)** شیء قیمت خالی `{}` خطای 500 می‌داد و Batch تا مهلت در `extracting` می‌ماند.
- **(P2)** run حساب در حال حذف هرگز بسته نمی‌شد و می‌توانست ۱۰۰ جای هر دور انقضا را بگیرد.
- **(P3)** `"1000"` و `true` به‌عنوان عدد پذیرفته می‌شد. schema رشته خالی را مجاز می‌دانست ولی اعتبارسنج رد می‌کرد. هر دو هم‌راستا شدند.
- **(P3، ثبت‌شده)** شروع تکراری مدل پس از timeout مبهم؛ در بخش محدودیت‌ها آمده است.


- **n8n بایت عکس را دریافت نمی‌کند.** اصلاح‌شده در [ADR-033](ADR-033-n8n-run-photo-links.md): لینک امضاشده هر عکس با حذف metadata.
- **workflow n8n ساخته نشده است.** فقط schema ورودی و خروجی در `n8n/schemas/` است. آزمون‌ها n8n را با HTTP جعلی شبیه‌سازی می‌کنند.
- **تأیید مقدار پیشنهادی از ربات ساخته نشده است.** کارت محصول استخراج‌شده با «بخشی تأییدنشده دارد» رد می‌شود. تأیید از API با PATCH و `status: confirmed` ممکن است. دکمه «تأیید مقدارهای پیشنهادی» (FR-032) برش بعدی است.
- **اصلاح از ربات منشأ را عوض می‌کند.** پاسخ به کارت (ADR-029) کل پیش‌نویس را با منشأ `manual_override` دوباره می‌سازد، پس evidence فیلدهای دست‌نخورده هم دستی می‌شود.
- **عکسی که یک بار خوانده شد دوباره خوانده نمی‌شود.** اگر محصولات استخراج‌شده رد شوند، عکس‌هایشان به run بعدی نمی‌روند. فروشنده باید عکس تازه بفرستد یا محصول را دستی ثبت کند.
- **محصول API عکس را claim نمی‌کند.** فقط ارجاع نسخه جاری آن دیده می‌شود. اگر محصول API بایگانی شود، عکسش دوباره «تازه» حساب می‌شود.
- **شروع تکراری ممکن است.** اگر n8n درخواست را بپذیرد ولی پاسخ گم شود، retry دوباره شروع می‌کند و مدل دوباره اجرا می‌شود. callback دوم با بدنه متفاوت `409` می‌گیرد و هزینه آن ثبت نمی‌شود.
- **callback از اینترنت عمومی رد نمی‌شود.** n8n مستقل است (`ai.smartystudio.co.uk`) و ممکن است از نشانی عمومی برگردد. حفاظت فقط امضا، پنجره زمانی و وضعیت run است. محدودکردن مسیر به شبکه داخلی در Caddy تصمیم عملیات است.
- ویس، CSV، OCR برگه قیمت و خوشه‌بندی چندعکسی ساخته نشده‌اند.
- هزینه به ریال یا اعتبار تبدیل نمی‌شود. Quote و رزرو گام ۵ است.
- n8n واقعی، provider و ربات زنده آزموده نشده‌اند.
