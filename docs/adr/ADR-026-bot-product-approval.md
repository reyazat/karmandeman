# ADR-026 — تأیید محصول (Gate A) از دکمه ربات

تاریخ: ۲۹ اکتبر ۲۰۲۶. وضعیت: تصمیم فنی برش یازدهم گام ۳، ادامه [ADR-025](ADR-025-bot-product-command.md) و [ADR-019](ADR-019-reopen-cancel-and-approval-integrity.md) (PRD E05، §۶). **مجوز intake واقعی در production، انتشار یا پایان گام ۲ نیست.**

## زمینه

پس از ADR-025 فروشنده محصول را در ربات ثبت می‌کرد، ولی Gate A فقط با API بود. گام ۳ «تأیید انسانی» را در همان برش عمودی می‌خواهد.

## تصمیم

۱. **دکمه:** پاسخ `/product` یک دکمه «تأیید محصول» دارد با `callback_data` برابر `product:approve:{شناسه عمومی محصول}:{شماره نسخه}` (حداکثر ۵۹ بایت، زیر سقف ۶۴ تلگرام). پاسخ نام نرمال‌شده، تعداد عکس‌ها، قیمت و واحد را نشان می‌دهد، یعنی همان نسخه‌ای که دکمه تأیید می‌کند.

۲. **اجرا:** callback فقط در گفتگوی خصوصی با شناسه برابر فرستنده، برای حساب در حال حذف نبودن و پس از onboarding پذیرفته می‌شود. الگوی داده سخت‌گیر است (UUID و عدد مثبت تا ۶ رقم). سپس همان `ApproveProductRevisionAction` اجرا می‌شود: رضایت، قفل Workspace، Policy، رد محصول بایگانی‌شده و پروژه لغوشده، **برابری دقیق نسخه**، فیلدهای تأییدنشده و `approval_mac`.
   - داده callback اعتماد ایجاد نمی‌کند. محصول Workspace دیگر با پاسخ «محصول یافت نشد» رد می‌شود، همان پاسخ محصول ناموجود.
   - دکمه کهنه پس از اصلاح محصول (نسخه تازه‌تر) تأیید نمی‌کند (PRD §۶).
   - کلید idempotency از شناسه همان فشار دکمه (callback id) ساخته می‌شود، نه از محصول و نسخه. پس هر فشار تازه همه بررسی‌ها را دوباره اجرا می‌کند: دکمه‌ای که پس از اصلاح، رد یا لغو زده شود پیام همان وضعیت را می‌گیرد، نه «تأیید شد». فشار دوباره روی محصول تغییرنکرده چیز تازه‌ای تأیید نمی‌کند و `version` پروژه بالا نمی‌رود. retry همان update تلگرام با `update_id` حذف می‌شود.
   - هر رد، از جمله خطاهای idempotency و خطای ناشناخته دامنه، با پیام پاسخ داده می‌شود و exception بیرون نمی‌رود. پس تراکنش webhook و پاسخ ACK دکمه commit می‌شوند و تلگرام update را دوباره نمی‌فرستد.

## محدودیت‌ها و کار باز

- اصلاح و رد محصول از ربات ساخته نشده است. پاسخ `/product` می‌گوید محصول اشتباه را تأیید نکن. رد هنوز فقط با API است.
- **رد محصول عکس‌هایش را آزاد می‌کند:** محصولی که رد (archive) شود، علامت ربات عکس‌هایش (ADR-025) را برمی‌دارد، پس `/product` بعدی همان عکس‌ها را می‌گیرد.
- «پایان ورودی» و تأیید Batch و دریافت JSON از ربات ساخته نشده‌اند و با API انجام می‌شوند.
- تعارض ثبت‌شده ADR-019 با PRD §۶ باقی است: Gate A در پروژه `product_approved` بدون reopen مجاز است. ربات فقط در پروژه `collecting_input` محصول می‌سازد. دکمه قدیمی پس از تأیید Batch، اگر نسخه تغییر نکرده باشد، فقط «تأیید شد» را برای همان نسخه تأییدشده تکرار می‌کند و چیز تازه‌ای تأیید نمی‌کند. تصمیم مالک محصول پیش از گام ۵ لازم است.
